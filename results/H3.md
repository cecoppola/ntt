## 3. Test rewrite plan

The five tests already support both bases through `harness_meta -> bi_env_base()` and `mpz_from_limbs/mpz_to_limbs` in harness.h; the oracle is GMP in each. They run today in decimal with `LIMB_BASE=10` (mnaccept runs the unit step without it, so binary). So "rewrite" is mostly: make decimal the only base (flip `bi_decimal` to a constant 1 / set 1 in `harness_meta`), delete the binary arms, and re-check each against GMP.

## 4. What replaces the independent two-pipeline cross-check

What the binary pipeline gave: the same digits by a different radix path (binary limbs, 4 primes, todec Barrett radix conversion, ecalc.c:787-831 T1/T2/digit-residue). Compared with the decimal pipeline it shares the NTT/RNS engine, `rns_mul`, bit-for-bit.
After removal the standing checks are:
- Decimal run's own VERIFY: T1 (`T*(P+Q) == X*Q + R` and P, Q residues modulo 8 primes above 2^62, verify.c `t1_q`), T2 (50-digit windows at 6-8 known offsets, recomputed independently: `tier2_range`), digit residue (digits streamed to file equal X mod q: mn_out.c / `out_stage`). These are base-independent identities and remain the only verifier above 1e11.
- Reference digit files (`ecalc/ref/`, GMP binary-splitting by `ref/gen_e.c`, a base-2 path independent of ecalc; local clone has only gen_e.c, files live on the clusters): `e_1000000.sha256`, `e_10000000.sha256`, `e_100000000.txt`, `e_1000000000.txt` (about 1 GB; mnaccept's `refall` requires 1e9 + the 1e6/1e7 hashes), 4e10 as `~/ntt/ecalc/results/e_4e10.out` (about 40 GB packed/ASCII; sha1 43c84e49...), 1e11 as `~/V214/e_1e11.sha1` (578f5efb...) and `~/ref1e11*`. No reference above 1e11 (results/A37CMP.md:37). Compared with `ecalc/digcmp.sh` (packed parts via `tools/unpack_digits --cmp`). Sizes quoted are measured from the d (digit) count, not stat'ed (files not present locally).
- Therefore after 28.5 the regression compares the decimal pipeline with GMP's independent generator at 1e6..1e9 (every run), 4e10 and 1e11 (`--full`), instead of a second ecalc pipeline. What is lost: an independent ecalc implementation at sizes **above 1e11** (a binary run at 4e10 was possible before). Keep `todec.c` and `t_mul_base2.c` in `archive:binary_pipeline/` so a binary comparison can be rebuilt from commit 0298fe2 (tag it: `git tag pre-28.5-binary 0298fe2`, recommended, not done here).
- mnaccept.sh: line 121-128 loop over `b in 2 10` becomes the decimal-only run; `accept.sh` BASE variable removed.

Paper section 9: **the paper source is not in the repo** (no .tex or paper directory in git; `~/apucode/epaper.pdf` exists outside the repo but its text does not extract, `pdftotext` returns nothing, so it is image-only and I could not see section 9). I cannot say which paper is meant (this PDF is likely the external reference paper; "paper 285.7 s" in ecalc.c:826 refers to it). The text to amend, per PLAN 28.5: remove the claim of an independent binary/decimal-conversion pipeline as cross-check, and say verification is T1/T2/digit residues plus GMP reference digits up to 1e11. Also ecalc.c's printed "paper A22 (4e10)" line disappears with the binary path.
