Branch `p13-P3`. **The EC_NP parameterisation commit for agent S: `32101f8`** (first working build: `03d3e82`,
which adds only the t_crt generalisation; S should rebuild on the branch head).

Switch: `ECALC_NP=3|4` (default 4 — every default unchanged). `ECALC_NP=3` needs decimal limbs (the pipeline's
default); with `LIMB_BASE=2` it is refused at `rns_init` with a message (exit 1).

## Design

* **Prime subset**: the first three primes of the set, c = 240, 216, 207 (p_i = c 2^44 + 1). tests/t_primes prints all
  four subsets: this one has the largest product, 2^155.355, and so the largest margin; all four share the kernels
  (3 | c: 2^k and 3·2^k lengths, p < 2^52). Using primes 0..2 means no reordering anywhere: "prime p on device p"
  and "plane p" stay as they are.
* **The bound** (measured by exact GMP arithmetic in t_primes): a convolution coefficient is at most
  nterms·(B−1)², B = 10^18, so three primes reconstruct exactly for nterms ≤ 58 424 467 928 (2^35.766). Margin
  p0p1p2 / (n (B−1)²): 27.2x at 2^31, 13.6x at 2^32, **6.80x at 2^33**, 2.27x at 3·2^33 (the longest length the primes
  allow). Every product the primes can transform is inside the bound. Binary 2^64 limbs would allow only 2^27.36 terms,
  so four primes stay required there.
* **`ec_np`** (modarith.h, defined in crt.c): runtime prime count, read once from ECALC_NP by `ec_np_init()` (called
  by `crt_init`, `rns_init`, `rns_gconst`). `EC_NP` stays 4 as the array bound and the device count.
  `ec_np_check(nterms, decimal, where)`: aborts loudly if ec_np = 3 and the limbs are binary or nterms exceeds the
  bound; called by `rns_init`, `crt_carry_par4(_q)`, `rns_mul_mdev`, `rns_mul_batch`, `dist_core` and `mn_core`.
* **Three-prime CRT**: Garner's first two steps (x = r0 + t1 p0 + t2 p0 p1 < 2^156, 3 words) — `garner3` (CPU, crt.c)
  and `dgarner3` (GPU, rns_mul.c) — then `ec_words_to_dec3` (modarith.h): 3 divisions by 10^18 instead of dec4's 16,
  because the top word is < 2^28 and the second quotient < 2^37. The carry window is 3 digits + carry; the spill format
  stays 4 words (the last 0), so every spill merge (CPU, `db_add_spills`, the dist tiers) is unchanged.
  `k_crt_batch` takes the prime count from `struct gconst` (`g.np`), so its signature and every call site are unchanged.
  Measured, CPU CRT 2^26 decimal coefficients at T = 192: 4 primes 0.377 s, **3 primes 0.175 s (2.15x)**.
* **Tiers**:
  - batch-local (every prime of a product on its own APU): loops and plane counts over `ec_np`; `k_scatter4` leaves
    plane 3 unwritten.
  - mdev and the striped batch tier (prime d on device d): device 3 skips its transform with three primes and joins
    only the GPU CRT (which is striped over all four devices). Not load-balanced — see open issues.
  - dist (`dist_core`, `mn_core`, the transform cache's slot size): prime loops and plane sizing `ec_np · q`.
* **Plane pools**: with ec_np = 3, plane pool 0 is allocated at init to exactly 3 q (3/4 of the four-prime pool; q =
  2^(pool_log−2), or 3·2^(pool_log−3) with the B3 planes). Pool 1 (xb | sbuf | rbuf, one prime at a time) is
  unchanged at 3 q + 16 — so the planes drop by 1/7, not 1/4: **modelled 180.4 → 154.6 GB per node** at the 4e10
  configuration (pool 0 25.8 → 19.3 GB per APU, pool 1 19.3 GB), not the 135.3 of PLAN §29 E3 (which scaled both
  pools). The mdev tier's largest product is then capped by pool 0 (`mdev_pts()`: 3·2^(pool_log−2) points with the
  3·2^k lengths; four primes: 2^pool_log, unchanged).
