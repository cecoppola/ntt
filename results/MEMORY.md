## Topic summary

What this is: how ecalc maps and sizes device (HBM, 4 APUs per MI300A node) and host memory, and what the per-node ceiling is. Numbers are measured on aac6 (one node, 502 GB total) unless labelled modelled; the 576-node figures are modelled.

Current state (cross-checked with `ecalc/README.md`; where an item below says "off by default" the README row governs):
- **Layout.** One arena per APU holds both bs parities plus the dm extra, laid out by `region_need` / `dm_layout` / `tree_need_dev` (§A-mem, §M11); the block pool keeps a reserved tail for the reciprocal's largest block, so there is **zero in-phase hipMalloc** at every size run (§M11 v4: 10¹¹ on one node, device 431.2 GB, node peak 445 of 502 GB). `ECALC_DM_POOL` was deleted (§I item 5). The arena is a VMM range in whole 2 GiB chunks (`DB_POOL_VMM`, default on); `DM_TIGHT` defaults on with it (§L114, §T114 context); `BS_ARENA_ROOM` default 0.14 (0.16 until Q99, 2026-10-25) and `BS_SEED_FILL` default 128 (§AS15; user decisions of 2026-09-27/28); `BS_SEED_PULL` default 1 since 2026-10-12 (§K8b, README) although the K8b ABBA never completed in this file.
- **Host.** X never lives on the host and the seeds stream straight into the regions: host HWM at 4 × 10¹⁰ fell 48.8 → 11.7 GB (§H); at 10¹¹ about 14 GB.
- **Init floor.** Init time is 0.06–0.075 s/GB × bytes mapped, a kernel page-clearing cost on one lock that no allocation form, thread count or reordering beats (§I, §K8, §K8b, §P3, §MAP15). Seeds overlapped with the mapping (§I item 3); 3·2ᵏ planes on below 5 × 10¹⁰ digits at one node (§I item 4; the 3·2ᵏ caps were later removed by SIMP, see `results/CODE_REDUCTION.md §SIMP` and the README row of `ECALC_PLANE_CAP`).
- **Plane cap `run` (2026-10-25, new switch; the default since 2026-10-25, user decision: unset = `run`, `ECALC_PLANE_CAP=2^31` forces the old cap, `POOL_LOG` or `DIST_LOGN_TEST` given keeps the knobs as given, `ECALC_PE_PER_GPU=1` with `XSHMEM_PES_PER_GPU` > 1 keeps `fit`; the verbose line reads `run (default):` when unset; the models `mem_model.py` / `mn_model.py` still assume 2^31 unless cap is passed).** Q122 (aac7, m): `ECALC_PLANE_CAP=2^30` cuts the fixed start-up of the two plane pools (25.8 GB per APU at 2^31) by 2.64 s [-2.98, -2.30] at 8e9 on one node and 2.05 s at 1e9, compute unchanged, digits identical (hash 3e78c1b2a0276963 at 8e9); about -2.8 s at 2 nodes with 8e9 per node. `ECALC_PLANE_CAP=run` takes 2^30 when the run's largest single product, the division's `2k + 8` limbs (k = limbs of 10^d + 4; `binsplit_div_product_limbs`), fits one mn plane of the 2^30 cap (`mn_logn_cap(g)` at pool_log 30: 2^30 at one node, 2^31 at two), else 2^31, and prints one `ECALC_PLANE_CAP=run:` line. That is 9.6e9 digits per node (assumed bound: above it the products are gridded and no 2^30 run was timed there; the model code found no abort at 2^30 below it, since the batch tier's largest product stays under the pool's 3·2^28 limbs to about 1.3e10 per node, modelled). `ECALC_PE_PER_GPU` is not modelled: `run` gives 2^31. Gate checks: unset unchanged; 8e9 one node picks 2^30 with the same hash; 1.2e10 one node picks 2^31; 2 nodes at 8e9 per node pick 2^30 (not yet run: coordinator's gate).
- **Ceilings (one node).** Three primes (default `ECALC_NP=3`): real edge 1.44 / 1.30 / 1.14 × 10¹¹ at caps 2³⁰ / 2³¹ / 3·2³⁰ (device + host HWM ≲ 524 GB runs, ≈ 529 GB is OOM-killed; §P13b). `mem_model.py` (exact to the byte against the C layout, §M13, §AS15, §DL15) is the tool; its 502/480 GB budget is conservative.

**`DM_TIGHT=1` (E2).** Reciprocal (`recip_db2`): r, r2, t1 reserved once after the seed at the last doubling's sizes (jl = ⌈k/2⌉ anchored: r at jl + 4, r2 at 2 jl + 4, t1 at take + jl + 2 + 8), blocks never move (r' copied from r2 into r's block at every doubling but the last); values identical, only capacities change. Block pool (`ext_take`, `db_pool_pack_large`): under DM_TIGHT large requests go by a packing rule (bs: highest free end outside the tail; dm: tail's back first, then highest free end), blocks may be carved from an extent's middle (`carve_at`).
