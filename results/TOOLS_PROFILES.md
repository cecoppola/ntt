## Topic summary

What this topic is: the scripts and tables around the engine that make runs reproducible and cheap to calibrate: machine profiles (`profiles/*.conf`), a registry of every environment switch (`ecalc/switches.tsv`, generated by `tools/switch_registry.py`), a startup `config:` line, profile loading (`tools/profile_load.py`, `tools/with_profile.sh`, `gate.sh --profile`), computed size values (`tools/plan_values.py`, `MNRUN_PRINT_ENV`), review dates for non-default switches (`ecalc/switches_review.tsv`), the log parser and rate-adjusted estimator (`ecalc/calib_table.py`), the environment probe (`archive:scripts_2026-10-23/envprobe.sh`), the model profile `aac7_s18`, the mnaccept fixes and the one-script target session (`ecalc/target_kit.sh`).

Current state (cross-checked against ecalc/README.md and RESULTS.md; the README owns switch defaults):
- Switch registry and review table: adopted. `switches.tsv` (266 rows when L5 landed; regenerate, do not hand-edit), `switches_gen.h` feeds the config line, `switch_registry.py --check` runs inside `gate.sh --build`, and the README review table is generated between markers. Review warnings never fail the gate (T27, merged).
- Profiles: C01 templates exist (`profiles/aac7.conf`, `archive:scripts_2026-10-23/aac6.conf`, `target.conf.template`). ## T27 — parameter system: computed size values and review dates for settings

Question: (A) can every setting that depends on digits or node count be computed in one place from (digits, nodes, profile), equal to today's hand values at tested sizes? (B) can every experimental, test-only or fallback switch carry an owner and review date, warning (not failing) when it passes?

Change (branch `t27`, merged; no ecalc C source changed, no digit can change):
- `ecalc/mnrun.sh`: `MNRUN_PRINT_ENV=1` (default 0) runs the whole launch computation (planner pool, heap by SHMEM implementation, `FI_UNIVERSE_SIZE`, libfabric defaults) and prints `export K=V` lines instead of calling srun; no allocation needed.
- `tools/plan_values.py [--profile P] [--line FILE] [--ecalc PATH] [--exports] DIGITS NODES`: asks `mnrun.sh` and the planner (`MN_PLAN_ONLY`); `--line` removes a typed line's size-dependent keys, recomputes and prints MATCH / DIFF / EXTRA / NO-CONSUMER (exit 1 on DIFF or `plan REFUSED`); `--exports` gives export lines for a launch without `mnrun.sh`.
- `ecalc/switches_review.tsv` (93 hand rows: name, class, owner, review date, note); `switch_registry.py` adds `owner` and `review` columns, `--check` prints `WARN` lines (exit unchanged) for a passed date, an experiment/test-only switch without a row, or a row for a gone switch; `--review`, `--today`; a README review table is generated between markers. `doccheck.py` prints `[review]` lines; `gate.sh --build` prints their count.

Part A, what was typed by hand: pool and heap on the target runbook (1536 / 2048M) and the private draft profile; `MN_GROUPS` at 576 (equals the code default schedule, so typing it changes nothing); one runbook key with no reader (NO-CONSUMER). Left as is: the kit's a3 pool formula (a harness buffer size), the kit's s2chk share 6.441e10 per node (to move to the 3.82e13 share in target preparation), aac6 CPX pool/plane-cap (machine-dependent, not size).

Results (m, plan-only on the aac7 login node, SHMEM build of main b60e34d):
