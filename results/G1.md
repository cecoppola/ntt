## Result (measured)

Both runs stalled in the gather (printed "chain" 4.89 s and 6.00 s, normal 1.2-1.5 s; milder than C10's 15.8-19.2 s). All timestamps are
CLOCK_REALTIME of the 4 nodes (one comm PE per node; PE n = node n); node clocks agree to the ms level (the late PE's signals reach its peers within 0.2-3 ms).

| | r1 | r2 |
|---|---|---|
| window length (gather incl. host prelude), all 4 nodes | 4.849-4.852 s | 5.949-5.953 s |
| PEs entering the allgather, seconds after window open | node 3 2.160, node 0 2.170, node 1 2.225 | node 3 2.175, node 0 2.199, node 2 2.220 |
| **late PE** (entry, host) | **node 2** 4.854 (aac7-n20), +2.63 s after the others | **node 1** 5.953 (aac7-n11), +3.73 s after the others |

| `db_from_bi` upload / first pool get | 0.000-0.001 s | 0.000-0.003 s |

## Conclusions

1. **The stall is not in the handshake or the transfer.** Once the last PE publishes its receive offsets, every peer's offset-wait ends within
   0.3 ms, the puts finish and all signals arrive within 3 ms. The remote-offset wait seen in the comm stats is the other PEs waiting for one PE that has not
   yet *entered* the allgather.
2. **The late PE is late before it calls the allgather**: in the host-side prelude of `mdb_to_host_all` (calloc/malloc, `db_to_bi` of its share
   (device->host), `hipSetDevice(0)`, `db_pool_alloc` x2, the H2D copy), i.e. local GPU/host work on one node, not communication.
3. **The late node differs per run** (node 2 in r1, node 1 in r2; different hosts and different ranks), and it is never rank 0 here. The three on-time PEs
   also need 2.16-2.23 s for the same prelude, which is already above the 1.2-1.5 s of a clean run, so all nodes may be slow in it, one much more so.
4. With C10 (gather time identical on all 4 nodes, upload refuted): the 15-19 s in C10 is then one node's prelude lasting that long.
5. **Not resolved**: which of the prelude steps (not timed in this run; the item that ran had only the allgather stamps). The new commit adds
   `hs_ts pre node N step S t_us T` after each step (start, alloc_host, db_to_bi_done, pool_alloc_done, h2d_done, allgather_done, d2h_done); needs one more
   queue item (same as 85, new binary) to localise. Caveat: 2 runs, one hold start; the stalls were milder than C10's.
