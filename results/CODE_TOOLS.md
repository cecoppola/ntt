## CODE_REDUCTION — shrinking the code

### Topic summary

- **What it was.** The 2026-10-11..13 campaign to make ecalc smaller without changing a digit: two read-only audits (AUD2 dead code, AUD3 structure), four removal merges (SHR2, SH3, SIMP, TREF), two settings-removal waves (W2A, W2B), a speed/size validation (L2), a clean-up round (CR4) and the decimal-vs-binary limb study (H1, H2, H4, H5). All merged to main unless noted.
- **Current state (m).**
  - Settings: 269 registry rows before wave 2 lane B, 185 after lane A, 170 after SHR2, 145 after CR4; `ecalc/switches.tsv` now has 101 rows (regenerated by `tools/switch_registry.py`).
  - Code: SHR2 -1531 lines, SH3 -261, SIMP -418 (ecalc sources), TREF -404 production, W2A about -1800 removed (about -1500 net). Every step was gated at 1 and 2 nodes with identical digits.
  - Single-node flow is the device DKM division at every size (SIMP); the 1-node 10^9 gate runs the production division.
  - Only the top-level checkpoint set (`ECALC_CKPT_TOP`) remains; there is no restart inside a run (D11).
  - Gone: TCP transport, SOS/OSHMEM build branches, the spill primitive, 3·2^k distributed planes, the `B4` strategy form, the host product tier (`rns_mul` host path). `ECALC_OUT_PACKED` default is 2 (60-bit packed, D5).
  - Limbs are decimal only (H4; branch `h4`, tag `pre-28.5-binary`): `LIMB_BASE` other than 10 fails loudly. Binary limbs were 1.9x (10^9) to 2.2x (10^10) slower (H5, m).
- **Validation (L2).** Digit-safe at 10^11 and speed-neutral at 6.441e10: 1e11 identical, new - old -0.18 s [-0.88, +0.52], 16 + 16 runs (m). Removed paths were off at the defaults, so only SIMP, B3 (null) and H4/H5 needed timing.
- **Still open.** `k_store`/`k_copy_h2d` partly merged (SH3); AUD3 items below; the X2 + cut last-group symmetric-offset hazard (when the last group is cut, `COMM_LAYER_VSLOT_POOL=1` with two exchanges in flight makes a different pool allocation sequence; documented, no guard built; text in `archive:results_merged_2026-10-25/CODE_REDUCTION_removed.md §O8`).

### §AUD3 — where ecalc's algorithms and code structure can be simpler and smaller (open items only)

Lines are net removed, time/memory modeled.
- **5** Size 1 through the sharded driver: about -310; the risk is memory (the one-node peak is laid out for the dbig flow; `mdb_shift` at g = 1 copies, 29 GB per copy of Q at 6.44e10); needs a 1-node ABBA and `mem_report`.
- **6** P24 as the only multi-node product form: about -50, partly overtaken by D18 (P24 is the multi-node default); +4 GiB per APU in pool 0 at 2-16 nodes.
- **8** One output-writer machinery: partly done (the dead 8-byte packed write path, `mn_out_share_src`, one `x_bg` output init; about -2 net). Left: size-1 (`x_bg`, `x_hi`) versus multi-node (`mn_out_early`) writer flows; different thread and gate structures, not mergeable without GPU gates.
- **9** `mdb_add_shifted` is already one body (`rns_dist.c`); folding it into `mdb_shift_gt` would change its round and pool pattern, not done.
- **10** One transform cache: done as dead-code removal (t10): the held full-slot path never allocated at any setting, the mn partial-slot machinery is the only cache code. Giving `mul_grid` partial slots is a behavior change (new 1-node pool use); needs an ABBA first.
- **13** (user decision) drop the SHMEM data path of device exchanges (about -120): kept until the target's A3 stage has run.
- Smaller: `mn_group`'s transform-node subset (`gt`, `tr`) is a leftover of `MN_TOPO_GROUP`; `mn_prod_cut_x1` never triggers at target sizes; the two start-up self-tests (`mn_selftest`, `mn_selftest_layered`) overlap.
- Done: items 1-4 (SIMP), 7 (moot: `mn.c` has the single `tree_level`), 11 and 12 (D5, D11).

### §SIMP — one single-node division flow, DKM only, no 3·2^k distributed planes, one grid planner (AUD3 items 1-4)

Results (m): plan sweep (`MN_PLAN_ONLY`, `BS_LAYOUT_ONLY`, 119 points x 2 files, five settings): 0 differ in 5 x 238 files. Gates on aac7: 2 nodes PASS (22.27 s), 1 node PASS (10.63 s), `mnaccept` unit/e9/grid/mn/corr 18 passed, 0 failed. ecalc 1 .. 10^5 digits prefix-identical; `t_newton` quotient section 320 divisions identical to GMP.
**Timing, 10^10 digits, 1 node, ABBA 4 rounds: A (main) 26.85 s, B (SIMP) 18.54 s; B - A = -8.31 s, 95 % CI [-9.68, -6.93].** Phases: dm 5.5 -> 1.7 s, 10dP 0.9 -> 0.0, bs 8.5 -> 6.7, T1 0.0 -> 0.5. Above about 1.9e10 digits the flow was already the device flow.
Verdict: adopted, digits identical at every size tested, planner byte-identical.
Open: `recip_db2` has a pre-existing outlier (1 of 1648 `t_newton` checks: the reciprocal at nq 131075, k 65538 was -22 units from GMP's floor against the +-8 bound; see `results/COMPUTE.md §RECIP`); `dm_layout` still sizes the size-1 division below 1.9e10 digits for the full-length set (larger than DKM needs, never short); `t_cap.c` keeps a mirror of the old 3·2^k caps.

### §TREF — a test reference product, and the host product tier removed

The tests' reference (`ecalc/tests/tref.h`: `tref_check`, `tref_faults`) compares a product with GMP up to 2^21 product limbs and above that by the residue form. Verdict (m): it catches every injected fault (0 missed, both forms) and agrees with the old reference on every case (83 products by value, 6 large by cross-acceptance); the host tier is removed; merged to main.
Open: the tests lost the host tier as an independent code path; the replacement independence is the residue form and the device path at two plane sizes (`t_mul` §1, §2; `t_arith primes`; `t_dbig`).

## TOOLS_PROFILES — tools and the parameter system

Scope: the tools under `tools/`, the scripts of `ecalc/`, and the profile/parameter system. Where this section and the code disagree, the code (each tool's `--help` or header) wins.

### Tool inventory

Every file in `tools/` is listed once. Python tools are stdlib only and host only unless noted.

| tool | what it does |
|---|---|
| `gate.sh` | the build-and-digit gate (`TESTING.md` §2): builds, runs, compares digits; runs doccheck, the registry check, `profile_load.py --validate-all`, `xshmem_api_check.py` and the Python unit tests first |
| `doccheck.py` | read-only check that the docs match the tree (`TESTING.md` §8) |
| `switch_registry.py` | generates `ecalc/switches.tsv`, `switches_gen.h` and the switch table of `ecalc/README.md`; `--check` verifies them |
| `profile_load.py` | loads and validates a machine profile (`profiles/*.conf`): `NAME`, `--validate`, `--validate-all`, `--show`, `--run -- CMD`, `--line` (the launch line), `--check` (drift) |
| `plan_values.py` | the size-dependent launch values of (digits, nodes, profile) through `mnrun.sh` and the planner (`MNRUN_PRINT_ENV=1`, `MN_PLAN_ONLY`); `--exports` prints `export K=V` lines for a launch without `mnrun.sh`; `--fit` prints the memory-fit report (exit 1 when the run does not fit) |
| `xshmem_api_check.py` | every `XAPI` function of `ecalc/xshmem.h` exists in both backends |
| `comm_id_audit.py` | audit of the xshmem communicator ids (collisions, out-of-domain runs) for PE counts 1..N |
| `initchk.py` | flags slow hosts from a multi-node run's own log (first-run init time above 3x the allocation median) |
| `nodescreen.sh`, `nodescreen_tab.py` | fast pre-run screen of every node of an allocation (local memory and upload check, one short single-node run, optional multi-node job); the table and the `EXCLUDE` list; `--health` and `--refuse-ue` read the EDAC error counters |
| `nodesnap.sh` | state of this node (meminfo, amd-smi, NIC counters, health) in `## name` sections |
| `stress/stress.sh`, `stress/nicdiff.sh` | the pool/CRT stress harness (factorial arms of repeated runs in one hold); `nicdiff` turns before/after node snapshots into a NIC delta |
| `aac7q.sh`, `aac7q_item_template.sh` | the standing work-queue runner for the aac7 login node (per-user node allowance read from Slurm, items with `# KEY=` headers) and its item template |
| `unpack_digits.c` | packed part files to the ASCII file, or compare with a reference without writing (`--cmp`); built by `make tools` in `ecalc/` |
| `test_unpack.py` | host test of `unpack_digits` (ASCII and packed forms, corrupted limb, changed byte) |
| `wbench.c` | the part-file writer's I/O pattern without a GPU run, to measure a file system's write and read-back rate; built by `make tools` |

Scripts in `ecalc/`: `mnrun.sh` (multi-process launcher; `MNRUN_PRINT_ENV=1` prints instead of launching), `mnaccept.sh` (standing regression), `digcmp.sh` (digit compare), `gres.sh` (GRES detection shared by the launchers), `aac7env.sh` (aac7 environment), `mn_model.py`, `mem_model.py`, `topo_check.py` (see `ecalc/README.md`). Python unit tests of the tools are in `tests/` (`python3 -m unittest discover -s tests`). Target-side scripts (ladder, bench, probe, config) are under `target/`.

### Current state

- **Switch registry.** `ecalc/switches.tsv` is generated (never hand-edited); `switches_gen.h` feeds the `config:` line; `switch_registry.py --check` runs inside `gate.sh --build`. The unknown-name guard stays (launcher-only names exempt by prefix); the old review-date table was removed (user decision, 2026-11).
- **Profiles.** `profiles/aac7.conf` holds the aac7 settings and its launch line (`LAUNCH_LINE_KEYS`); the target's template is `target/config/target.conf.template`, filled by `target/probe/gen_conf.py`. Precedence: explicit environment > profile > code default (`profiles/README.md`).
- **Computed size values (T27).** Pool, heap and `FI_UNIVERSE_SIZE` come from `mnrun.sh` and the planner, not from typed values. A hand-typed pool/heap line can be compared with `plan_values.py` (MATCH / DIFF / EXTRA / NO-CONSUMER); the target runbook's typed pool and heap are stale under the X2 default (the plan asks 2304 / 2816M); changing the runbook is the user's decision.
- **Calibration.** `total = a + b / r` (r = the run's own all-to-all rate) reduced the residual sd from 11.9 s to 1.6 s on 63 clean 4-node runs (mod on m). The parser/fit tool `calib_table.py` is no longer in the tree (`archive:CODE_TOOLS_2026-11-10.md` §B07 has its interface). Caveat: where an arm changes the exchange itself, the rate covariate moves with the arm.
- **mnaccept.sh.** Shared TMP on multi-node holds, reference-directory search, `refneed` (a missing reference is "reference missing", never VERIFY FAILED), `--mem=0` on steps, `--skip-grid`; steps in `TESTING.md` §3.
- **Target bring-up package.** Archived (the old one-script session named `t_comm`, `COMM_TRANSPORT=shmem` and `COMM_OFI`, removed with the plain SHMEM transport, Q103); its former interface is in `archive:CODE_TOOLS_2026-11-10.md`.
- **Environment probe and `aac7_s18` model profile** were not adopted (probe: `archive:scripts_2026-10-23/envprobe.sh`; the r256 bracket correlation of -0.98, n=6, is a hypothesis). The time-model fabric profiles in use are listed in `ALGORITHM.md` §11.

## SESSIONS — aac7 measurement sessions of September/October (results that still hold)

Labels: (m) measured, (d) derived, (i) inferred, (mod) modeled, (a) assumed. Times Eastern. The per-item sections are in `archive:repo_cl6_2026-10-25/results/SESSIONS.md`; originals in `archive:results_merged_2026-10-19/`.

- **`MN_T_CHUNK_MB=2048` is faster on aac7** (D2, S22): B - A = -40.6 s +- 11.1 (95 % CI), 16 of 16 rounds negative (pooled 24 rounds -42.3 s mean, 22 of 24 negative; mean total 436 -> 396 s); memory unchanged. The code default is 1024 MB (pool law, needed by the target); 2048 stays an aac7 profile-line choice; no target A/B was made.
- **Closed NO-GO on measurement:** S-2 division/reciprocal overlap (ceiling 25-34 s at 576 (mod), realistic 6-17 s, below the 30 s bar); A37-R1 GPU seed (at the target the seed ends at about 16 s against a 16.5 s init floor: gain 0-1 s (mod)); the 3-pass 2^31 NTT (13/9/9 forward 90.6 ms (m) against today's 89.9 ms; gate <= 80 ms). A37-R5 batch pipeline was judged "not worth it" but later built as `BS_BATCH_PIPE` (default 1 since D20; `results/COMPUTE.md §N3`).
- **Where the 10-node wall goes (S27):** direct exchanges cost 101 s per thread of 376 s (27 %), of which 61 % is skew (waiting for a slower node), not transport; transport variants (rot order, NIC rebinding, OFI-native signal) are dead ends (rot null on wall: +3.1 s, CI -1.0..+7.2). One node arrived about 20 s late at the reciprocal; S32 showed it follows the host (a stall in `db_from_bi` upload, 21-25 s), not the rank.
- **X2 (INTER2 + VSLOT_POOL, S31)** is -32 s (-8 %, clean rounds) at 10 nodes with +0.8 GB (m); both are built-in defaults. Its 576-node effect is unmeasured.
- **A rare crash exists:** a segfault in libamdhip64 from the VMM background mapper, about 3.5 % of 10-node runs on 2026-10-08 and 0.14 % per 2-node run (m); not cured by the former `ECALC_VMM_SAFE=2` (follow-up in `results/CORRECTNESS.md`).
- **Scaling data:** share ladder at 10 nodes: 410.6 s at 6.441e10, 464.4 s at 7.00e10, 528.5 s at 7.64e10 (time exponent about 1.5-1.9, above n log n; unexplained); memory linear at 28.4 GB per 1e10 digits per node (fixed about 173 GB on rank 0); the 8.1e10 share is stopped by the vslot rule (427.6 GB needed against 0.95 x the smallest MemAvailable 440.7 GB).
