# HEALTH — node health gate (C4) and per-APU memory guard / high-water (C5)
**Question.** (C4) Can the kit tell a node with uncorrectable memory errors (EDAC ue), a reboot, or NIC errors during our run from a healthy one? (C5) What does one APU really need (not the pool's reserved footprint at phase boundaries), and can a guard watch each APU's own memory?
**Change / branch.** Branch `health`. C4: `tools/nodehealth.sh` (EDAC ue/ce totals per node and per controller, boot time), used by `tools/nodescreen.sh` (columns ue, ce, boot; WARN on ue > 0; `--refuse-ue` puts the node on EXCLUDE; kit: `REMOTE_REFUSE_UE=1`) and by `remote/run/nodesnap.sh` (`## health`); `remote/run/lib.sh` `rl_nicdiff` adds FEC / pause / stall / drop deltas and the top-5 nodes, `rl_healthdiff` the EDAC and reboot delta; `s5_run.sh` writes `node_health`, `nic_delta_top5`; `report.sh` prints them. Test hook `NODEHEALTH_SYSFS_ROOT`. C5: `ecalc/nodemem.h`, `memsample.c`: the sampler reads each NUMA node's MemFree (APU k = node k) and prints `device_hwm_apu_gb=` at exit (rides the sampler: on with `ECALC_MEM_SAMPLE` or a guard, no new switch); `ECALC_MEM_GUARD_APU_GB` (default 0 = off) stops the run (rc 9) naming the APU; `ECALC_MEMSAMPLE_SYSFS_ROOT` test hook; `stair.sh` reads `device_hwm_apu_gb` when present (its step line names the source), else `device_peak_apu_gb`.
**Method.** aac7, 1 node, queue item 52 (measured 2026-11-01): `tools/gate.sh --build --nodes 1 --hold J --env ECALC_MEM_SAMPLE=5`; `tests/t_nodemem`; 1e10 digits with `ECALC_MEM_SAMPLE=2 ECALC_VERBOSE=2` on the aac7 launch line; guard tests with a mock tree and the real tree; `nodescreen.sh --no-mn`, and with `NODEHEALTH_SYSFS_ROOT` (mock ue=1) without and with `--refuse-ue`; `nodesnap.sh` before / after a 1e9 run and `rl_nicdiff` / `rl_healthdiff` on the pair. Discovery: every node has EDAC mc0-mc3 (`ue_count`, `ce_count`) and per NIC 1890 telemetry counters (`hni_pcs_*` FEC, `hni_pause_*`, `hni_*_paused_*`, `hni_*stall*`, `hni_llr_*`), so no counter is missing.

APUs 1-3 (40.96, 38.19, 41.48 against the plan 41.38) are the usable numbers. A `MemFree + file cache` variant would fix this; not done (needs the user's choice).
**Open issues.** (Review fixes 2026-11-01.) ## MEMFIT — per-APU free memory with the file cache, and a start-up per-APU check (user decisions Q140 items 1 and 2)
**Question.** (1) MemFree alone made APU 0 look nearly full (page cache sits in HBM); is MemFree + the reclaimable file cache the better "free memory per APU", and do GPU allocations show up as file pages? (2) Can the run refuse at start-up when an APU has less free memory than the planner's busiest-APU peak?
**Change / branch.** Branch `memfit` (base c51ea2e9). `nodemem.h nodemem_read`: MemFree and Active(file) + Inactive(file) of a NUMA node. `memsample.c`: `device_hwm_apu_gb` and the guard `ECALC_MEM_GUARD_APU_GB` now use free = MemFree + Active(file) + Inactive(file); the old MemFree-only figure is printed on a second line as `device_hwm_apu_memfree_gb=` (fields `apu_memfree=`, `per_apu_memfree_gb=`, `start_memfree_gb=`, `min_memfree_gb=`) for one release. Which one is used: the guard, `remote/run/stair.sh` and the kit's `device_hwm_apu_gb` all read the new figure (the name is unchanged, so stair.sh needed no edit); only the `_memfree_` line is the old one. `ecalc.c fit_apu_check` (new switch `ECALC_FIT_APU_CHECK=1`, default off): after the planner's fit and before the transport and the pools are opened, each APU the process drives (layout P: its own) needs free memory >= the planner's busiest-APU peak (`dev_apu_max`, the `per APU (max)` figure of `ECALC_FIT_PER_APU`; rank 0's layout) + the margin (`ECALC_MEM_GUARD_APU_GB` if set, else `ECALC_DEVICE_MARGIN_GB`, 5 GB); else rc 8 (as the budget check) with a message naming the APU, its free memory, the peak, the margin and the shortfall. A multi-node launch relies on the launcher to end the other ranks (this check runs before the transport opens; not tested at 2 nodes, no multi-node code touched).
**Method.** aac7, 1 node, queue item 58 (measured 2026-11-01): `tools/gate.sh --build --nodes 1 --hold J --env ECALC_MEM_SAMPLE=5`; 1e10 digits with `ECALC_MEM_SAMPLE=2 ECALC_VERBOSE=2 ECALC_FIT_APU_CHECK=1` on the aac7 launch line, with a 1 s sampler of every NUMA node's `meminfo` (MemFree, Active/Inactive (file and anon), Unevictable, Mapped, Shmem) on the compute node from 5 s before the run; the refusal with `ECALC_MEM_GUARD_APU_GB=1000` at 1e8; the default (switch off) at 1e8; `tests/t_nodemem` (mock meminfo with file pages), unit tests, registry, doccheck.

**Verdict.** Adopt MemFree + file cache as the per-APU free memory: it is the memory a run can really get (the kernel reclaims file cache on demand; the old figure called a node with 70 GB of reclaimable cache "full") and GPU allocations do not hide in it. The high-water drop is nearly the same either way (differences <= 0.6 GB here) because the run itself takes anon-like HBM; the difference is in the free level, which is what the guard and the start check compare. The start-up check is correct and refuses before GPU work; it stays off until the user adopts it. Caveat: the measured high-water on APU 0 (53.43 GB) exceeded the planner's busiest-APU peak (51.05 GB), so the check's margin should cover at least that gap (the 5 GB default does, 2.4 GB measured); the host-side NUMA-local memory (pinned staging, runtime) is taken from the same HBM and is not in `dev_apu_max`.
**Open issues.** The check uses rank 0's layout figure for every rank; with `XSHMEM_PES_PER_GPU` > 1 several PEs share one APU and the figure is not multiplied (not tested). Not run at 2 nodes (no multi-node code changed).
