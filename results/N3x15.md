# N3x (Phase 15 Batch 2, PLAN §37 row 3) — the radix-3 pass fused into the first 2ᵏ pass; 2ᵏ⁺² for small k

Branch `p15-N3x` from `main` f184d51 (B1). aac6 clone `~/ntt-N3x15`. Times Eastern. Every number is labelled **measured**,
**modelled** or **assumed**.

## 0. Feasibility note (written before any code)

**What costs today.** `ntt_fwd3` (`ntt3.c`) runs `k_r3_fwd` — one full read and write of the 3·2ᵏ points (radix-3 butterfly
over the thirds, then the twiddle w_n^(r·j)) — and then `ntt_fwd` over the three thirds; `ntt_inv3` mirrors it (`ntt_inv`,
then `k_r3_inv`). V3 measured the pass at 19.8 % of a 3·2²⁹ forward and 33–50 % at 3·2¹⁰ … 3·2¹⁷ (measured); L8 measured it
stand-alone at the copy speed (memory-bound, measured). 90 % of the transform time at 10¹¹ is in 3·2ᵏ lengths (L8, modelled
from measured batch-tier lines).

**Approach.**
1. *Forward fusion.* The first pass of `ntt_fwd` on a third is a b16 pass over the top stages (tile of 128 rows spaced
   2^s_lo apart × 16 adjacent columns). The three thirds' tiles at the same (row, column) positions are exactly the triples
   the radix-3 butterfly needs. A fused kernel loads the three tiles of one position set (24 values per thread instead of 8),
   does the radix-3 butterfly and the twiddle in registers (the same 8 canonical modmuls per 3 points as `k_r3_fwd`), then runs
   the b16 stages on each third in turn, reusing the one LDS buffer (a barrier between thirds). One read and one write of
   the data disappear. Built for the register-blocked 7-stage body (`k_b16r`, the default for logk ≥ 17) and for the tile
   kernel `k_b16<STG>` (the partial top pass of logk 13–16).
2. *Inverse fusion.* Mirror: the last pass of `ntt_inv` (the top b16 pass, which applies the m⁻¹ scale) runs the three
   thirds, keeps them in registers, and applies `k_r3_inv`'s arithmetic (the same operations in the same order) before the
   single store. Also covers `ntt_inv3_pw_y` (the pointwise product stays fused in the b1 pass at the other end).
3. *`pick_len` (k ≤ 12).* logk 10–12 have no b16 pass (the b1 pass is the whole transform), so no fusion there; a switch sets
   the smallest k for which 3·2ᵏ is taken, below it the 2ᵏ⁺² length (V3: 3·2¹⁰ costs 1.23× 2¹² per product, measured).
4. Everything behind one switch (`NTT_R3_FUSE`, default 0) plus the `pick_len` threshold (`RNS_R3_MINK`, default 10 = today).
   Other kernel configurations (NTT_MALL, H6 variants, NTT_MODMUL 2, the ds_swizzle exchange, a bottom-up plan whose top pass
   is partial) fall back to the old path.

**Why the digits cannot change.** Every transform output is canonical, hence unique: any exact computation of the same
transform gives the same bits. The fused kernels keep the same arithmetic anyway (same butterflies, same modmuls, same order
per point), so even the intermediate values are those of the old path. `pick_len`'s 2ᵏ⁺² gives the same exact product (the
CRT bound depends on the operand sizes, not on the transform length).

**Risks.** (a) Register pressure: 24 live values per thread in the fused b16r pass (≈ 48 extra VGPRs); occupancy is capped by
LDS (3 blocks/CU) at ≤ 170 VGPRs, so there is room, but spills would kill the gain — checked from the ISA/timing. (b) Fewer
blocks (a third as many) at small k and batch 1 — only the batch tier has small k and it runs large batches. (c) The r3
twiddle-table reads become strided within a block (rows 2^s_lo apart): the 512 KB table stays in L2. (d) The fused pass may
become compute-bound: +2.7 modmuls per point on a pass V3/K13b measured near the bandwidth. Expected recovery 60–80 %
(assumed). (e) The dist tier (`rns_dist.c`) calls `ntt_fwd3/ntt_inv3` too: it is covered by the same switch and tested.

**Test plan.** `t_ntt r3x`: every 3·2ᵏ length k = 10 … 29 and every 2ᵏ, k = 10 … 31, every prime, batch 1 and 3, forward,
inverse, inverse with the pointwise product in the three y layouts: switch on vs off **bitwise** (device compare) — plus the
old round-trip tests (`t_ntt3`). Then `t_mul`, `t_newton`, `t_dist`, e9 in both bases, `mnaccept --only unit,e9` and the `mn`
steps, 10¹¹ via `digcmp.sh` against `e_1e11.out`. Microbenchmark per length (old vs new, fwd / inv / fwd+inv_pw), then 10¹¹
on one node, off vs on, ≥ 3 runs each without the digit file, and one pair with it (both walls).

**Expected gain** (modelled from V3's measured pass shares, 70 % recovery assumed): batch tier ≈ −4 s, the 3·2²⁹ B pieces
(mdev, grids, reciprocal, division) ≈ −2…−4 s: **−6…−8 s at 10¹¹** (≈ 3 %); **−3…−4 s at the target** (leaf only). `pick_len`
at k ≤ 12: < 1 s (three levels of small products).

**Verdict: safe and worth it — build.**

## 1. What was built

- **`NTT_R3_FUSE`** (default 0; `ntt.c`, `ntt3.c`, `ntt.h`). `ntt_fwd3` / `ntt_inv3` / `ntt_inv3_pw_y` call the new
  `ntt_fwd_r3` / `ntt_inv_r3` when `ntt_r3_fusable(logk)` holds; otherwise the old path runs unchanged.
  - `k_b16r` (register-blocked 7-stage body) and `k_b16` (tile kernel, any stage count) get a template flag `R3`: the block
    handles the same tile position in the three thirds. Forward: 24 loads, the radix-3 stage in registers, then the stages on
    each third in turn with the one LDS buffer (a barrier between thirds). Inverse (the last pass): the stages on each third,
    kept in registers after the scale, then the radix-3 stage and one store. The pointwise product stays fused in the b1 pass.
  - Arithmetic: with 1 + w₃ + w₃² = 0 the butterfly needs one product, t = w₃(a₁ − a₂): y₁ = a₀ − a₂ + t, y₂ = a₀ − a₁ − t
    (ntt3.c forms four); the inverse's 3⁻¹ is folded into the last pass's scale ((3m)⁻¹ instead of m⁻¹). 5 modmuls per
    triple instead of 8 (forward) / 11 (inverse). Every value is canonical, so the outputs are those of the separate pass bit
    for bit (checked, §2) — the note's "same arithmetic" became "same canonical values".
  - Registers: unrolled over the thirds, the compiler kept each stage's twiddles live across them (forward 185–228 VGPRs,
    2 blocks/CU); the thirds now run in a rolled loop with the registers rotating through static indices: forward 102–108,
    inverse 128–142 VGPRs, no scratch (measured, `-Rpass-analysis=kernel-resource-usage`), so LDS still sets 3 blocks/CU.
    The non-R3 instantiations are within ±4 VGPRs of main's, no scratch.
  - Covered: k ≥ 13 (a b16 pass exists) in the kernel configuration of the defaults and the common switches (NTT_MODMUL 0/1,
    NTT_PLAN any, NTT_B1R any, NTT_B16_BODY 0/1, NTT_B16_STG any). No fused form (the old path): NTT_MALL, NTT_MODMUL=2,
    NTT_B16_XCHG=1, NTT_B16_VAR, NTT_B16_BODY=2, and k 10–12.
  - A one-line notice when the switch is read as on (so the logs show the path was taken).
- **`RNS_R3_MINK`** (default 10 = today; `rns_mul.c pick_len` only: lines 312–313 added, line 316 changed, `NTT_LOGN_MIN` →
  `r3_mink`): 3·2ᵏ only from k = RNS_R3_MINK on, clamped to 10–13 so no pool-sized product can change length.
- **Tests**: `t_ntt hash [KMAX2 KMAX3]` (a device hash of every transform's output; also built against main's tree with
  `-DT_NTT_OLD`), `t_ntt r3bench [KMIN KMAX]`; `tests/n3x_node.sh` (the node batches).

differ, both** — on the final kernels (commit 9ae489f, job 21616, s24-16, 26 s per run) and on the two earlier versions
