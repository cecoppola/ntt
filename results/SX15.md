## 1. The error bound E on X₀ − X (before corrections)

### 1.1 One Barrett estimate (every division step in the code)

Notation (`newton_db_divmod_shifted`, `divmod_shifted_dkm` / `dkm_est_db`, `mn_dkm_est`, `newton_mn_divmod`):
- B = 10¹⁸.
- A has n_a limbs, Q has n_q limbs, and k = n_a − n_q + 1.
- A_h = ⌊A / B^(n_q−1)⌋ < B^k (k limbs), and A_lo = A mod B^(n_q−1).
- μ has k + 1 limbs, and e_μ = μ − B^(n_q+k)/Q (real).
- The high product skips the grid pieces that lie wholly below limb k + 1 (`NEWTON_HIGHPROD`, default on). There are m of them,
  S is their sum, and each is < B^(k+1) (R114 §1.2), so 0 ≤ S < m·B^(k+1).
- X₀ = ⌊(A_h μ − S) / B^(k+1)⌋, and X = ⌊A/Q⌋ = A/Q − f with f ∈ [0, 1).

Exactly:

  (A_h μ − S)/B^(k+1) = A/Q − A_lo/Q + A_h e_μ / B^(k+1) − S/B^(k+1),

- 0 ≤ A_lo/Q < B^(n_q−1)/Q ≤ 1;
- |A_h e_μ / B^(k+1)| < |e_μ|/B =: β, because A_h < B^k;
- 0 ≤ S/B^(k+1) < m.

So X₀ − X = ⌊f − A_lo/Q + b − σ⌋ with f ∈ [0,1), A_lo/Q ∈ [0,1), |b| < β and σ ∈ [0,m). Hence

  **−(m + 1 + ⌈β⌉) ≤ X₀ − X ≤ ⌈β⌉**, i.e. **E_lo = m + 1 + ⌈β⌉ (X₀ below X), E_hi = ⌈β⌉ (X₀ above X)**.   (1)

These are the only error sources:
- the dropped A_lo, which only lowers;
- the skipped pieces, which only lower;
- μ, in either direction, by at most β.

The floor makes no further loss: it is the floor the true quotient has too.

### 1.2 β: the reciprocal's error

The final μ comes from the last doubling round (precision j → j' = k or h). The round reads u = ⌊Q_t r / B^(take−j)⌋ and forms
d = |u − B^(2j)|. Let ρ = B^take / Q_t ∈ (1, B], and let E_r be r's error in units of its last limb.

R415 §1.3 step 1 and R114 (1)/(4) give, including both cuts (δ₁, δ₂ ∈ {0,1}) and the middle product (bit-identical under R415's
fatal check):
- |E_r| ≤ (d + 2) ρ / B^j;
- the new iterate r' = r B^j ∓ corr has |E'| ≤ E_r²/ρ + 2r/B^j + 2 ≤ (d + 2)² ρ / B^(2j) + 2ρ + 3.

The steps from r' to μ each add at most one unit:
- the shifts by 2j − j' and j − k (floors, which also divide the error): ±1;
- Q_t ≠ Q when take < n_q: ≤ 1 unit (R415 step 4);
- DKM's view of μ's top k₂ + 1 limbs: ±1.

So:

  **|e_μ| ≤ (d + 2)² ρ / B^(2j) + 2ρ + 6**, rigorous given the arithmetic of the last round.   (2)

**The last round's d has j limbs in every log** (measured):
- 10¹¹ DKM: j 1388888890, d 1388888890 limbs;
- 10¹¹ no-DKM: j 2777777779, d 2777777779 limbs;
- every sweep size (§1.4).

So d < B^j, the first term is ≤ ρ(1 + 4B^(−j)), and |e_μ| ≤ 3ρ + 7 ≤ 3B + 7. Hence **β < 3 + 7/B and ⌈β⌉ ≤ 4**. From (1):

  **E_hi ≤ 4, E_lo ≤ m + 5**, provided the last round's d has at most j limbs (a limb count the code already has: `dn`, `d.n`).   (3)

This does not need R114 §1.5's multi-step chain. That chain's worst case is not closed for many cut rounds, since its interval
argument grows by about 2^n/ρ per round. (3) uses only the last round, so it holds however the chain got there. If d has j + 1
limbs, the exact form (2) is evaluated from d's top two limbs and Q's top limb, a handful of limb reads. If d has more than j + 1
limbs, the certificate is not claimed and the low product runs (the fallback, §2.3).

## 2. The guard-limb certificate

### 2.1 The statement

The run computes X with d digits after the point and prints d_out ≤ d of them. G = d − d_out is the number of guard digits. Write
X₀ = H·10^G + g with 0 ≤ g < 10^G. The printed digits are those of H.

**Claim.** If X − X₀ ∈ [−E_hi, E_lo] and **E_hi ≤ g ≤ 10^G − 1 − E_lo**, then ⌊X / 10^G⌋ = H, and the printed digits are exact.

**Proof.** X − H·10^G = g + (X − X₀) ∈ [g − E_hi, g + E_lo] ⊆ [0, 10^G − 1]. ∎

The sign convention follows (1). X₀ below X by up to E_lo needs room above g, and X₀ above X by up to E_hi needs room below it.

### 2.2 How many guard digits

- **Today, G = d − d_out = 8** at both 10¹¹ and 5.167 × 10¹³: d is rounded up to a multiple of 18.
- **G = 0 whenever d_out is a multiple of 18.** The guard must therefore be made explicit.
- The low digits of e are equidistributed, so **P(fail) ≈ (E_lo + E_hi + 1) / 10^G**:
  - G = 8, target E_lo + E_hi = 10: ≈ 1.1 × 10⁻⁷;
  - G = 8, 10¹¹ E = 7 + 4: ≈ 1.2 × 10⁻⁷.
- **Proposal: at least one whole guard limb**, d = 18·⌈(d_out + 18)/18⌉, so G ∈ [18, 35]. Then **P(fail) ≤ 12 / 10¹⁸ ≈ 10⁻¹⁷**.
  Even with a deliberately generous E = 64 (the code's correction limit) it is 1.3 × 10⁻¹⁶.
- **Cost:** one limb in 2.87 × 10¹² (+8 B per node; N may grow by one term). **0 s** (modelled). The printed digits are the same
  prefix.
- **Knock-on:** `mn_out`'s sidecar tail holds at most 23 digits (`char tail[24]`, `mn_out.h:49`; RECHECK's reader at `mn_out.c:844`).
  A guard limb needs it widened to ≥ 36. These are EW's / DL's files: a stage-2 item.

### 2.3 Where the check runs, and the fallback

The certificate is known the moment X₀ exists. That is the point where the code calls the writer hook today, before step 2's low
product.
- **Reading g:** the lowest two limbs of X₀. `db_limb` at size 1; `mdb_limb` at size > 1 (a small collective on the node holding
  limb 0).
- **E_lo, E_hi:** from m (the grid's own skipped count) and the last reciprocal round's d.n (kept from the reciprocal; +1 static).
- **If the certificate fails**, or d.n > j + 1: run today's path unchanged: step 2's low product, the corrections, R's residues, and
  the deferred tail patch (`ECALC_CORR_PATCH`). Q, the window Aw and X are all still alive at that point, so no memory has to be kept
  longer.
- **Cost of a failure:** exactly today's: **21.1 + 1.2 + 0.7 = 22.9 s at 10¹¹** (measured) and **13.7 s at the target** (modelled).
  It happens with probability ≈ 10⁻¹⁷.
- With the certificate passing there are no corrections, so the tail patch has nothing to do (dx = 0).

### 3.2 What the skip leaves unguarded

With the certificate, the printed digits are exact **if the arithmetic that produced X₀ was right**. That arithmetic is the
reciprocal's last round, step 2's A·μ product and the assembly. Today a fault there shows up as T1 (b) FAILED, or as > 64 corrections
(fatal). With the skip it would print wrong digits silently, unless it hits a T2 window.
- Faults **earlier** in the reciprocal are not a concern: Newton heals them, or they trip the overshoot / repeat / middle-product
  checks (R415's fatal), or they break (3)'s d.n condition, which triggers the fallback.
- **X_hi is not affected:** step 1 keeps its low product.

### 3.3 Can R's range be checked without R?

- **Residues cannot do it.** Residues are ring homomorphisms. They fix R mod q, and any R mod q is consistent with X·Q − T(P+Q). The
  inequality 0 ≤ R < Q is an order statement no residue encodes.
- **What decides it is X·Q's limbs around n_q**, the top of R, a middle product.
  - At the target that is 5 of the 8 pieces of step 2's low product (modelled from the plan's 2 × 4 grid).
  - It saves little, and it still needs a borrow from below.
- **What can be checked cheaply** (the (b) row): the **arithmetic trace**.
  - For a cut product, t_cut = Σ_formed C_ij B^(o_ij), so t_cut ≡ Σ_formed (A_i mod q)(B_j mod q) B^(o_ij) (mod q). The check reads
    the operand pieces and t once (`db_mod_qs` / `mdb_mod_qs` on views).
  - At the target that is ≈ 4 × 1.43 × 10¹² limbs × 8 B / 576 ≈ 80 GB per node, ≈ 0.1 s at HBM rates (assumed). Not built.
  - The same applies to the reciprocal's last Q_t·r and r·d, and to r' = r B^j ∓ corr.
- **Step 1's identity A_hi ≡ X_hi·Q + R1 (mod q) is exact and nearly free** (R1 exists; its residues cost 0.7 s at 10¹¹, measured
  for R). With 0 ≤ R1 < Q from step 1's corrections, it proves X_hi as T1 does today.
  - Step 1 uses the same μ as step 2 (its top k₁ + 1 limbs, k₁ ≈ k₂). A zero or small dx₁ is a direct runtime witness that μ is
    good. This is a heuristic, not a proof.

### 3.4 Off the clock (a1 / a2): what must be kept or saved

- **The division check needs** X (in the part files, + the sidecar's guard tail), Q, A mod B^w and T(P+Q) mod q.
  - A mod B^w = (S mod B^(w−dl)) B^dl. At the target w − dl = n_q + 2 − dl = **6 limbs of S** (n_q 2870555555560, dl 2870555555556).
  - T(P+Q) mod q comes from the sidecar's P, Q residues, which are verified against the recurrence.
  - So **only Q is large**: 2.87 × 10¹² limbs × 8 B = 23.0 TB, **39.9 GB per node** (exact arithmetic on the plan's n_q).
    TARGET.md models the whole `.top` set at ≈ 42 GB per node at 5.1 × 10¹³.
- **(a1) keeps Q, and R1 or its window**, in memory past the division (≈ 40 + 40 GB per node, modelled). It runs step 2's low product
  and T1 after the part file.
  - Whether 80 GB fits beside the output stage has to be checked with `mem_model` (assumed to fit: the division's peak is higher).
- **(a2) writes Q after the clock** (≈ 40 s at 1 GB/s, assumed) for a RECHECK that becomes a mini-run with pools. Such a RECHECK today
  is "no pools, no computation, ≈ 1.5 min packed". Its new cost is about 3–4 min on 576 nodes (modelled: read Q ≈ 40 s,
  X ≈ 1.5 min, X·Q mod B^w ≈ 27 s).
