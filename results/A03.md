# A03 -- initchk: slow-host check from a run's own log (2026-10-11, CPU only, existing logs)

Labels: m = measured (existing aac7 logs), s = synthetic (made-up logs for the parser), p = policy (adopted by the user 2026-10-11).

## Design
`tools/initchk.py` (python3, no dependencies). Input: one multi-node log (srun `--label` output, `MNRUN_LABEL=1`) or a directory of
per-node logs. Per node it reads, when printed: `rns_init` (`ECALC_INIT_TL=1` line "peer access done", else "init: rns_init X s"),
`map` (longest "APU<d> arena: N chunks mapped in X s"), `region` ("init: region pools X s"), `transport` ("transport opened before
rns_init"), and `upload` ("recip ts2 node N host H ... db_from_bi(upload) +X", `NEWTON_MN_RECIP_TS=2`, the one line that names its host).
Ratio = value / median over the nodes, per metric. FLAG when ratio > `--threshold` (default 3) and value - median >= `--min-excess`
(default 2 s; avoids flagging sub-second noise). Needs >= 3 nodes reporting a metric. Exit 0 = no flag, 3 = flagged, 2 = could not parse.
Unlabelled logs are supported but each column is then sorted on its own (a row is not one node) and only `upload` flags name a host.

## Findings
1. **The slow host does NOT show in init (m).** In both real positive controls (s32 b_perm1, b_base2: logs in the 2026-10-10 session
   archive on aac7) the host aac7-n01 has rns_init 18.1 / 19.1 s against medians 16.4 / 16.6 s (1.11x / 1.15x) and region pools
   9.4 / 10.1 s against 8.95 / 9.04 (1.05x / 1.12x). Its stall is the first device upload in the reciprocal stage (db_from_bi, after
   the run is ~13 min in), 20.9 / 25.2 s against ~1 s. An init-time rule at 3x therefore cannot flag it (separating threshold for
   init: none; the host is only ~1.1x). A node 3x slow in init itself would be a different fault; none has been seen.
2. **The upload line does separate it (m):** healthy nodes 0.97-1.28 s (ratio <= 1.3), the slow host 20.8-25.3x. Any threshold between
   1.5 and 20 separates; 3 (the adopted value) sits 2.3x above the healthy maximum and 6.9x below the lowest observed stall.
3. **No real log is rank-labelled and no real log with ECALC_INIT_TL=1 contains the slow host** (the 2026-10-08 s32/s34 runs predate the tl
   lines; the later 4-node runs excluded the host). So the init check is validated only for the no-false-positive side (healthy
   init ratios 0.8-1.15 rns_init, <= 1.34 region/transport over 8 real runs) and, for the flagging side, synthetic logs.
4. The `upload` line exists only with `NEWTON_MN_RECIP_TS=2` and appears ~13 min into a 1e11 run (after init). At that point the check is a
   post-run diagnosis (rerun without the host), not a pre-run gate. The cold probe (t_nodechk cold, T10) stays off until a positive control exists.

## Recommended threshold
3x the median, min excess 2 s (the adopted policy); keep the defaults. Healthy maximum observed 1.15 (rns_init) and 1.34 (region/transport,
6-node run), so 3 has no false positive in 8 real runs. Run it on the first multi-node run of the allocation.

## Exact wiring for a06 (ecalc/target_kit.sh; not edited by a03)
`SELF_DIR` is `ecalc/`, so the script is `$SELF_DIR/../tools/initchk.py`. After the first multi-node run of a stage that sets
ECALC_INIT_TL=1 (s2chk already does; for a4 add `ECALC_INIT_TL=1` and, optionally, `NEWTON_MN_RECIP_TS=2` to its env words, and
`MNRUN_LABEL=1` in the `env` before mnrun.sh), add a helper and call it:

```bash
initchk_log() {   # initchk_log <log> <n> -- slow-host policy (3x allocation median); prints into the summary, never fails the stage
    local f=$1 n=$2 out rc
    [ "$n" -ge 3 ] || { summary "    initchk (n=$n): skipped (needs >= 3 nodes for a median)"; return; }
    command -v python3 >/dev/null 2>&1 && [ -f "$SELF_DIR/../tools/initchk.py" ] || { summary "    initchk: python3 or tools/initchk.py missing"; return; }
    out=$(python3 -I "$SELF_DIR/../tools/initchk.py" --quiet "$f" 2>&1); rc=$?
    case $rc in
        0) summary "    initchk (n=$n): OK, no node above 3x the allocation median" ;;
        3) summary "    initchk (n=$n): SLOW-HOST FLAG -- rerun without the host (sbatch -x / MNRUN_EXCLUDE_HOSTS):"; echo "$out" | grep '^FLAG' | sed 's/^/      /' >> "$SUMMARY" ;;
        *) summary "    initchk (n=$n): could not parse (needs ECALC_INIT_TL=1; rc $rc)" ;;
    esac
}
```
and, in `stage_s2chk` directly after `s2chk_verdict "$nlf" "$n"` (same place in the a4 stage after its first multi-node run):
`            initchk_log "$nlf" "$n"`.
Policy text for the kit header/summary: "Slow-host policy (adopted 2026-10-11): a node whose first-run init (rns_init) or first device upload (db_from_bi) is more than 3x the
allocation median is flagged by tools/initchk.py; the user reruns without that host. The cold node probe (t_nodechk cold) stays off by default until a positive control exists."
Caveat for a06: with MNRUN_LABEL=1 the log is parsed per rank; without it, names appear only for the upload line.
